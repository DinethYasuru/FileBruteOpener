# File Security Analyzer & Authorized Password Recovery Lab

An educational, browser-only tool for identifying how a file is encrypted and recovering
access to **your own** password-protected files. It is built for a bounded, authorized-use
scope: checking a single known password, searching a finite dictionary you supply, or
searching a capped mask keyspace (a charset and length you choose). There is no
unrestricted/open-ended brute-force mode.

## Running it

No install, no server, no build step. Double-click `index.html` (or open it with
`File → Open` in any modern browser). Everything — crypto, UI, and the Web Worker pool —
runs client-side from that single page; nothing is uploaded anywhere.

## What it does

1. **Identify** a file's format from magic bytes, with a Shannon-entropy fallback for
   unrecognized high-entropy (likely encrypted/compressed) content.
2. **Verify** whether a password you already know unlocks the file.
3. **Search** a finite candidate space (dictionary list or mask) across a pool of Web
   Workers, with live progress and multi-core scaling.
4. **Generate** valid encrypted test files for a password you choose, so you can exercise
   the tool against real files that also open correctly in standard software.
5. **Benchmark** CPU worker scaling and detect WebGPU availability (GPU is detected only;
   candidate testing always runs on CPU workers for portability and correctness).
6. **Export** job history as JSON or CSV, and see SHA-256 / entropy / format details for
   every file analyzed.

"Candidate search" always means: a dictionary list you provide (capped at 2,000,000
entries), or a mask (charset × length) capped at 25,000,000 combinations. Both caps are
enforced in `js/app.js` and exist to keep this a bounded recovery tool, not an open brute-force
engine.

## How password verification works (no content decryption needed)

For every supported format, checking a candidate password does **not** require decrypting
the file's actual content:

- **PDF R2–R4**: the Standard Security Handler's `/U` (and `/O`) entries are themselves
  derived from the file's encryption key via MD5/RC4 (ISO 32000-1 Algorithm 2 / 2.A). A
  candidate is correct iff it reproduces the stored `/U` or `/O` value.
- **PDF R5–R6**: `/U` and `/O` embed a SHA-256-family hash of the password plus a stored
  salt (Algorithm 2.A / the R6-hardened Algorithm 2.B). No AES decryption of page content
  is involved in the check itself (R6's hardening *round function* does use AES-128-CBC
  internally as part of the hash, but that's hashing machinery, not content decryption).
- **ZIP ZipCrypto**: a 12-byte encryption header precedes the data; decrypting it with a
  candidate key and checking it against the entry's known CRC-32 (top 2 bytes) is enough.
- **ZIP WinZip AES**: PBKDF2-HMAC-SHA1 over the candidate derives an encryption key, an
  authentication key, and a 2-byte password-verification value stored in the file. A real
  match is then confirmed via the full HMAC-SHA1 authentication code (no CRC check, no
  false positives), still without touching AES-decrypting the payload.

## Architecture

```
index.html          Dashboard UI shell
css/style.css        Styling
js/utils.js          Byte helpers, CRC32, Shannon entropy, AES-CBC-no-pad helper
js/md5.js            Dependency-free MD5 (not provided by Web Crypto)
js/rc4.js             RC4 stream cipher
js/pdf-auth.js       PDF tokenizer/parser + Standard Security Handler (R2-R6) auth & key derivation
js/zip-auth.js       ZIP central-directory parsing, ZipCrypto + WinZip AES verification
js/identify.js        Magic-byte identification + entropy heuristic, format-specific detail
js/worker-pool.js    Self-contained Blob-URL Web Worker pool for candidate search
js/gpu.js             WebGPU detection + CPU worker-scaling benchmark
js/generator.js      Encrypted PDF/ZIP test-file generator
js/app.js             Dashboard wiring: state, panels, job history, export
local-service/        Optional, separate: real-tool sample generation + detection-only
                       inspection for RAR/7z/Office/GPG (see local-service/README.md)
```

### Why a Blob-URL worker pool instead of worker files

Workers are built at runtime from a `Blob` whose source is assembled from the *actual*
function bodies of the shared crypto helpers (via `Function.prototype.toString`), not from
separate worker `.js` files fetched over the network. This is what lets the whole app run
from a **double-clicked `index.html`** with no server — `file://` pages generally can't
`fetch()` sibling files due to browser CORS restrictions, but inline `<script>` tags and
Blob-URL workers both work fine.

## Limitations

- No ZIP64 support (entries/files beyond the 4 GiB / 65535-entry classic ZIP limits).
- The test generator can't produce WinZip AES-192 files: browsers' Web Crypto API does not
  implement 192-bit AES keys at all (128 and 256 only). This doesn't affect *verification* of
  real AES-192 files, since checking a candidate password only needs PBKDF2-HMAC-SHA1 and
  HMAC-SHA1 — no AES operation is involved in the check itself.
- RAR, 7z, legacy/CFB-wrapped Office, and OpenPGP are detected but not verified — these
  formats need substantially more format-specific code (RAR5 AES-256+Argon2-like KDF, 7z's
  AES+LZMA container, OOXML Agile/Standard encryption schemas, OpenPGP's S2K/packet
  framework) that was out of scope for this build.
- For a DEFLATE-compressed ZipCrypto entry, only the classic 2-byte header check is possible
  (no inflate implementation here), which carries a small (~1/65536) false-positive rate per
  candidate - noticeable on a multi-million-candidate mask search. A STORE-method entry (as
  this app's own generator produces) gets a definitive full CRC-32 check instead. Either way,
  a hit should be re-confirmed by actually opening the file.
- Candidate search is intentionally bounded (dictionary or capped mask) — this is a recovery
  tool for files you have the right to access, not an unrestricted cracking tool.

## Authorized use

Use this only on files you own or have explicit permission to attempt recovery on. It is
built for legitimate password recovery and for learning how these encryption formats and
their authentication algorithms actually work.
